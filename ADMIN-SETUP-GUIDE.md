# CashNote Website Admin — Setup Guide

## What it manages
- Home hero title, accent, copy
- Features and About page main headings
- Product-tour caption
- Product-tour poster image and optional MP4/WEBM video
- Three public product screenshots (transactions, profiles, preferences)

## Render setup
The admin API stores small JSON content and uploaded media on a Render Persistent Disk mounted at `/var/data`. No external database is required. The API service is configured as Render Starter with a 1 GB persistent disk because Render Free services do not provide durable persistent disks. If you keep the API on Free, admin edits/uploads can be lost when the service restarts or redeploys.

1. Deploy the updated `render.yaml` Blueprint (or apply the same settings to the existing `cashnote-download-api` service).
2. Confirm the API service has a persistent disk mounted at `/var/data`.
3. Set `ADMIN_PASSWORD` in Render Environment to a unique password of at least 16 characters.
4. Set `ADMIN_SESSION_SECRET` to a random secret of at least 32 characters (Render Blueprint generates one automatically).
5. Confirm `PUBLIC_API_URL=https://cashnote-download-api.onrender.com`, `CASHNOTE_DATA_DIR=/var/data/cashnote-site`, and `ALLOWED_ORIGINS=https://cashnote-website.onrender.com`.
6. Deploy the static website and API.
7. Open `https://cashnote-download-api.onrender.com/admin/` and sign in.

## Security notes
- Admin password is stored only as a Render environment variable; do not commit it to Git.
- Admin UI is served from the API origin so its signed, HttpOnly, SameSite=Strict cookie is first-party (no third-party cookie dependency). Sessions expire after eight hours.
- Login attempts are rate-limited in memory.
- Uploads are restricted by media type and size; filenames are generated by the server.
- Admin page is marked noindex and blocked in robots.txt. This is not a substitute for keeping the password secret.
- Keep a backup of `/var/data/cashnote-site` before large edits.

## Upload guidance
Use compressed WebP/JPEG screenshots (ideally under 1 MB each). Keep the product video under 50 MB and encode as MP4 (H.264/AAC) for broad browser support. If no video is uploaded, the animated CSS product-tour visual remains visible automatically.
